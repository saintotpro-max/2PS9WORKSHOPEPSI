 PART 13 — KEY::COMPOSER — ATTACK COMPOSER (GLM)
-------------------------------------------------------------------------------
Definition : orchestrateur de GENERATION de scenarios d'attaque
(VOCABULAIRE : dire "orchestrateur de generation de scenarios",
PAS "simulateur d'attaque" dans le dossier).
Interface : vue "Red Crew" = terminal du jeu Ren'Py (D16), sans cout
supplementaire.
Flow : selecteur niveau 1-5 -> prompt GLM -> script python/bash genere ->
REVUE HUMAINE -> arsenal versionne dans Git -> execution REELLE depuis
le PC Attaquant -> effet observable sur le SI.
Timing : generation mardi-mercredi AMONT ; jeudi = replay de scripts
geles UNIQUEMENT (R-14 : jamais de dependance GLM le vendredi).
Conformite : l'IA generative est explicitement autorisee pour produire
du code et des jeux de tests [V] ; l'attaque reste reelle, pas une
simulation graphique [V].

 PART 16 — KEY::RENPY — FAISABILITE + LIBS + METRIQUES
-------------------------------------------------------------------------------
MOTEUR [V 2026-10-19] :
- open source, Python/Cython, ~6.9k etoiles, gratuit meme usage commercial
- build DESKTOP : network + requests FONCTIONNENT
- build NAVIGATEUR (WebAssembly) : reseau NON supporte (sockets et
  requests bloqués par le sandbox navigateur) ; contournement officiel
  renpy.fetch en maturation (headers en ajout)
- CONSEQUENCE : Ren'Py = application desktop sur le PC Hote, jamais en
  web build. Sans impact demo : l'ecran du jury est le PC Hote.

INTEGRATION DE LIBS [V, doc officielle + communaute] :

  pip install --target game/python-packages <lib> puis import dans

- LIMITATION : extensions C (numpy, pandas, matplotlib) ne fonctionnent
  PAS sans recompiler le moteur -> si calcul scientifique requis :

 PART 17 — KEY::DOUBLEFACE — CONCEPT "ALPHA : DOUBLE FACE" [D]
-------------------------------------------------------------------------------
PRINCIPE : tout jouer en Ren'Py a condition que chaque choix du jeu
declenche une VRAIE action sur la VRAIE plateforme. Le jeu raconte,
la chaine travaille en dessous.

SCENE 0 — L'ARRIVEE : hall de la Banque Alpha (fictive). Trois portes :
le capuchon (hacker), le badge (SOC) et l'ombre (client, role offert au
jury local). Le joueur choisit sa route. Detail : jeu v2.1.

ROUTE HACKER (tourne sur le PC ATTAQUANT — l'attaque doit partir
d'un poste distinct [V]) :

- L'arsenal : menu de 3 niveaux (sous-ensemble des 5 niveaux de l'Attack
  Composer, etiquettes metier) ; chaque item lance un script gele
- Le coup : terminal style a l'ecran, trafic REEL ; sur le second
  ecran (cockpit du jeu) les courbes montent pour de vrai
- La riposte : le jeu interroge l'API de sante en boucle ; quand la
  plateforme s'est auto-reparee, le hacker "voit" la porte se
  refermer

ROUTE LUMINEUSE (operateur SOC, PC Hote) :
- L'alerte : l'anomalie ML s'affiche ; le joueur consulte
  l'assistant RAG -> VRAIE requete Ollama, vraie reponse affichee
- Le choix pedagogique : "intervenir a la main" (le jeu REFUSE et
  explique la sanction 0/5 [V]) OU "faire confiance a l'automatisation"
  (seule voie)
- La preuve : le joueur declenche lui-meme une nouvelle transaction,
  qui reussit

FIN COMMUNE — "ZERO-TOUCH" : la banque n'a pas eu besoin d'un humain.

CONFORMITE :
- aucune simulation graphique [V] : si le script echoue, le jeu
  l'affiche tel quel, pas de faux succes
- le cockpit (dashboard) est fait dans Ren'Py (D16) alors que le sujet impose
  React + Tailwind [V p.4] : risque assume ;
  Ren'Py = ecran narration + telecommande + cockpit
- l'operateur ne repare JAMAIS : zero-touch
- clip Chrono : captures reelles continues ; Ren'Py fournit juste les
  titres de sequences (autorises)
BONUS PITCH : rejouable — vendredi, si le jury veut revoir l'autre
face, relancer l'autre route en 2 min.
FINALE NATIONALE : le jury est a distance (Teams) : le role client est
joue par l'equipe ; demo limitee a 3 min (attaque + reprise).
